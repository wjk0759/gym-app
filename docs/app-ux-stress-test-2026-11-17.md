# 叫练 App 用户路径压力测试报告

- 日期：2026-11-17
- 测试端：macOS，iPhone 17 模拟器（6.9 英寸），Debug 构建
- 测试方式：真机式 UI 导航 + 本地已建档/已生成计划状态 + 代码审查
- 覆盖：今日、记录、教练、发现、我的、设置、器械库、动作库、变化、身体打卡、饮食记录/添加食物、计划训练会话
- 自动化基线：`FitAITests` 121/121、`FitAIUITests` 4/4、后端 606 passed、QA 76/76

## 一、结论

核心功能没有发现崩溃或数据写入阻塞；计划、训练会话、饮食记录、器械库和设置都能进入并完成主操作。

但 UI 层有几个明显不符合用户习惯的问题，其中 **悬浮 Tab Bar 遮挡内容** 和 **身体打卡输入无无障碍标签** 应优先修。

## 三、关键证据

### F1 悬浮 Tab Bar 遮挡

- “记录身体”快捷卡：`frame = (20.0, 727.7, 84.3, 76.3)`，`maxY = 804.0`
- 悬浮 Tab Bar：`frame = (0, 791, 402, 83)`，`minY = 791`
- 垂直重叠约 **13pt**。
- 初始截图同时可见：
  - 记录页日历最后一行被 Tab Bar 压住
  - “我的”当前目标卡下半部分被压住
  - 设置页训练提醒卡被压住
  - 器械库空状态主按钮“从器械库添加”被压住
  - 变化页“拍一张/相册”按钮被压住
- 滚动后这些按钮可以移到 Tab Bar 上方并恢复可点击，所以属于布局/安全区问题，不是永久不可点击。

建议：Tab Bar 用真正的 `safeAreaInset`，或所有二级页面 `toolbar(.hidden, for: .tabBar)`；至少保证首屏主 CTA 在 Tab Bar 上方。

### F2 身体打卡输入无标签

XCUITest 读取到：

```text
textFields labels = [("", "0"), ("", "0"), ("", "0")]
```

三个输入框都没有 label，placeholder 都是“0”。VoiceOver 用户无法知道哪个是体重、体脂、腰围。

建议为输入框加 `.accessibilityLabel("体重")` / `"体脂率"` / `"腰围"`，并保留单位提示。

### F3 记录食物默认早餐

- 时间：20:51
- 路径：今日饮食 → 我的记录 → 记录食物
- 餐次 Picker 初始选中“早餐”
- 用户若直接搜索并添加，食物会写到早餐

建议使用 `suggestedMeal`（按当前时间）或最近一次记录餐次作为初始值；至少 17:00 后默认晚餐。

### F4 0% 宏量进度条像已填充

截图：蛋白 `0 / 144g`、脂肪 `0 / 65g` 下方都有一条接近全宽的浅绿色 track。代码：

```swift
Capsule().fill(color.opacity(0.20))
```

`color` 是 `Theme.primary`（青柠），所以 0 值也有明显绿色。建议 track 用 `Theme.stroke` 或灰色，只有实际值部分使用主色。

### F5 “回到今天”冗余

记录页选中 17 日（今天）时，顶部仍显示“回到今天”。建议 `selectedDate` 是今天时隐藏或禁用。

### F6 饮食记录入口不直观

“今日饮食”首屏是“定制食谱”，只有“拍照识别”“本周计划”，没有“添加食物”。用户要记录已吃食物，必须先切“我的记录”。建议：

- 如果当天已有记录或当前时间已过餐点，默认进“我的记录”
- 或在“定制食谱”顶部增加“记一笔”主按钮

### F8 QA 计划生成静默失败

`AppStore.generatePlan()` 第一行：

```swift
guard profile.isOnboarded else { return }
```

QA bypass 只绕过登录，不设置 `isOnboarded`，所以点“生成计划”无任何反馈。建议 QA bypass 同步种子一个已建档 profile + 可选示例计划，或 Debug 下显示 toast。

## 四、已通过的核心路径

- 五个 Tab 切换、Tab 重复点击回根、设置页打开/返回
- 发现 → 器械库 → 器械目录详情
- 动作库列表、搜索框、筛选 chips、动作卡片、底部已选动作按钮
- 记录 → 变化趋势/进展照片页
- 今日饮食 → 定制食谱/我的记录切换
- 我的记录 → 记录食物 → 餐次 Picker、搜索、外食/食物库列表、手动添加入口
- 身体打卡 sheet 打开、三项输入、保存按钮
- 本地种入计划后：今日计划卡 → 安排训练 → 开始训练 → 3 组记录 → 休息倒计时/跳过 → 查看训练总结
- 教练页欢迎卡、快速开始、输入框、附件入口
- 无崩溃、无白屏、无导航死链

## 五、测试限制

- 没有登录生产账号，没有执行真实后端写入、支付、短信、Apple 登录
- 没有测试 IAP（外部商品/协议仍 BLOCKED）
- 没有测试 Watch、HealthKit、相机/相册权限
- 使用的是 iPhone 17 模拟器；小屏设备（SE/mini）遮挡问题可能更明显
- 计划生成使用本地种入状态；真实 AI 计划生成、同步和跨设备刷新未在本轮重跑

## 六、建议修复顺序

1. **F1 Tab Bar 安全区**：全局修复，收益最大。
2. **F2 身体打卡 accessibility label**：实现成本低，直接影响无障碍。
3. **F3 记录食物默认餐次**：避免用户数据记错。
4. **F4 宏量 track 颜色** / **F5 回到今天** / **F6 饮食记录入口**：体验打磨。
5. **F8 QA bypass 种子**：恢复 UI 自动化对计划生成的覆盖。
6. **F7 “记录”命名/信息架构**：需要产品确认，不急于改代码。
7. **F9 Debug 开发服务器提示**：仅影响 Debug 包。
