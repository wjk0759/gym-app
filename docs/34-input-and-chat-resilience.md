# 输入与教练请求韧性

## 键盘收起

iOS 端的输入框不再依赖每个页面单独实现“完成”按钮：

- `RootView` 安装 `KeyboardDismissInstaller`，在 `UIWindow` 上挂一个不拦截业务点击的 `UITapGestureRecognizer`。
- 点击输入框以外的区域会调用 `endEditing(true)`；点击输入框本身不会被拦截，方便在多个输入框之间切换。
- `AppScrollView` 继续使用 `.scrollDismissesKeyboard(.interactively)`，下滑内容也会收起键盘。
- 教练页额外提供键盘工具栏“收起”，以及发送前主动解除焦点。
- 键盘弹出时暂停 `WeatherSkyLayer` 动画，降低输入和发送时的主线程/GPU 压力。

## 教练请求超时与停止

教练对话、照片点评都可能遇到网络或模型服务长时间不返回。现在请求生命周期有明确出口：

- `APIClient` 的 `coach/chat`、`agent/chat` 请求超时为 50 秒，其余接口默认 90 秒。
- `AppStore` 对 Agent 对话、旧版文字对话、照片点评统一设置 45 秒看门狗；超时后结束“正在输入”状态，写入一条可理解的提示；Agent 文本请求保留重试入口。
- 请求带有 request ID；旧请求完成或被取消后，不能覆盖新请求的 UI 状态。
- 正在回复时，输入栏右侧显示“停止”按钮；停止、清空对话、切换账号都会取消进行中的教练请求。
- 取消过的请求不会重复追加助手消息。
- 重试或发送新消息时，会先移除上一条超时气泡，避免同一个问题堆出多条相同提示。
- Agent 请求携带 `request_id`；后端对已完成的同一请求做短时缓存，客户端超时后点“重试”会取回原结果，不会重复生成动作或计划。多 worker 部署应把缓存替换为 Redis/数据库任务表。
- 一次动作卡可能包含多天“跳过训练”；执行后会保存整批撤销状态，撤销会一起恢复，而不是只恢复最后一天。
- 后端允许一次工具调用最多 7 个动作；整周取消/多天跳过应在一轮内完成，不再因为 3 个动作上限被拆成多轮。教练 Agent 的推理强度单独使用 `LLM_AGENT_REASONING_EFFORT=high`，避免 `max` 带来的额外延迟。
- 体重、体脂、腰围等身体数据只能走 `log_body_metric`；`remember` 会拒绝身体数据，防止 Agent 反复调用记忆工具耗尽步骤。
- AI 计划生成耗时可能接近 100 秒，iOS 的 `plans/generate` 超时已放宽到 150 秒；计划生成单独使用 `LLM_PLAN_REASONING_EFFORT=high`。如果不需要 AI 计划，后端保持 `LLM_PLAN_ENABLED=false` 使用毫秒级模板。

## 验收清单

- 登录、注册、资料编辑、饮食、训练、教练等页面：输入后点击空白、下滑、点其他按钮都能收起键盘。
- 教练页输入后按键盘“收起”能立即关闭键盘。
- 断网/后端无响应时，教练页 45 秒内退出“正在输入”，出现重试；停止按钮可立即结束。
- 拍照点评同样在超时后退出等待，不把 `isReplying` 卡在 true。
- 键盘出现时天气动画暂停，键盘收起后恢复；切后台、切 Tab 仍暂停。
