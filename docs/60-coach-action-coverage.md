## 8. 当前最大缺口

1. **跨能力多动作**：已支持最多 5 个独立动作的组合确认（饮食记录/饮食修改/饮食删除/计划餐/改期/跳过/加练/力量/训练修改/训练删除/单个动作调整/整天动作调整/计划恢复/计划配置/体重/目标/有氧/避开食物/避开动作/档案器械）；其他能力仍单动作。同一饮食内的多餐/多食物已支持一张卡。
2. **设置/账户类**：远程 AI、会员、隐私还没有教练 action。
3. **个人资料字段**：昵称、性别、身高、经验、伤病、档案器械都可在教练修改；档案器械只是入门条件，个人器械库仍是精确来源。
4. **训练中操作**：逐组、休息计时、动作替换仍要页面；这是刻意保留的实时交互例外，不是缺口。
5. **通用卡片**：每加能力仍要写新 SwiftUI 卡片。
6. **缺口闭环**：已记录 `CoachActionGap`，但还没有自动转成待补能力或运营看板。
7. **页面缓存**：依赖本地副本的页面已监听 revision（饮食/周餐单/日程/复盘/记忆/目标日期）；直接读 `AppStore` 的器械、体型分析、档案页随 store 自动刷新，不额外监听。

### 2026-11-16 已补的全局上下文

- 标点/空格全切 token，再重组数字/单位/日期/时间/范围。
- 一句话多餐分组，一张多餐卡一次确认、一次撤销。
- pending 卡上的追加/修正优先原地更新：饮食、体重、改期、目标、有氧。
- 其他卡片遇到修正/追加先保留卡，不再静默丢弃。
- 跨能力多动作：`coach.batch` 最多 5 个动作，一次确认、整组撤销；目前覆盖饮食记录/饮食修改/饮食删除/计划餐/改期/跳过/加练/力量/训练修改/训练删除/单个动作调整/整天动作调整/计划恢复/计划配置/体重/目标/有氧/避开食物/避开动作/档案器械。计划餐允许同一餐次能力出现多次（如同时跳过午餐和晚餐），但同日期同餐次的重复动作会被拒绝。
- 语义意图路由 fallback：规则链未命中且消息像动作请求时，用能力清单让 LLM 选能力；模型只选能力，不写库。清单现在导入即注册全部 49 个能力（除 `coach.answer`），此前 custom_food/equipment/favorite/dislike/body_analysis 只有在规则先命中后才会进入清单，语义 fallback 可能选不到。
- 饮食已确认的单条记录支持“记错了”撤销重记；pending 卡支持替换单项。
- 已执行的多条/多餐饮食记录现在也支持“记错了”：旧记录先保留，纠正卡确认时在同一事务里作废旧 action 并写入合并后的全部条目；其他食物和其他餐次不会丢，也不会重复。
- 替换后撤销会恢复替换前的日志；batch 内的饮食子动作也能纠错；draft 从当前仍存在的日志重建，用户删掉的条目不会被带回。
- 纠正未指明餐次时按食物名推断餐次；同一食物出现在多餐时先问“哪一餐”，不猜。
- 严格模式下，器械库/通用器械/严格开关变化后，如果当前或未来计划含不可用动作，计划页会主动提示重排；可重新生成或暂不重排。过去和已跳过训练日不参与判断。
- 身体记录支持教练删除：按日期、按项（体重/体脂/腰围/臂围/腿围）或“最近一条”；一行的其他指标保留，整行删空才移除；撤销可恢复。
- AI 记忆页监听 `.profile` revision，教练记住/更新偏好后重新拉取记忆列表。
- 开始训练支持指定训练日：“从后天的训练开始”“开始周三的训练”；指定日已完成/已跳过时会明确提示。
- 计划历史恢复支持“恢复上一版计划”“回到之前那版训练计划”“恢复版本2”；确认后切换，撤销恢复原计划。
- `memory.forget` 支持“忘掉早睡这条记忆”“删除关于早上的记忆”；多条匹配时先追问，删除可撤销。
- `profile.update` 支持昵称、性别、身高、经验；`profile.update_injuries` 支持伤病更新，并检查当前计划是否有冲突动作。
- `equipment.add` 支持把识别结果或说出的器械加入个人库；`equipment.update` 支持改名；`equipment.delete` 支持删除并撤销。删除后会修剪 iOS 已同步缓存。
- `body.apply_analysis` 支持把最近一次体型分析应用到当前计划：按分析重点给对应动作 +1 组，生成新版本计划；可撤销并恢复分析的 applied 状态。
- `diet.favorite_food` 支持“收藏鸡胸肉”“取消收藏米饭”；自定义食物会按 custom key 收藏，结果通过 cloud extras 同步。
- `diet.custom_food` 支持从一句话创建自定义食物：名称 + 每100g 热量/蛋白质/碳水/脂肪；确认后写入自定义食物库，撤销删除。
- `training.dislike_exercise` 支持“不喜欢深蹲”“以后别安排硬拉”“可以安排卧推了”；写入不喜欢列表，服务端计划池会排除，撤销恢复。
- 伤病部分恢复支持“膝盖好了但腰还疼”“膝盖好了，腰还疼”“膝盖恢复了但腰还疼”；先分句再判断，只移除明确恢复的部位；“膝盖伤好了”也只移除膝盖；“腰不舒服/腰还没好”同样视为仍在恢复，不会被一起清掉。单说“膝盖不舒服/腰还没好”不会替换其他伤病记录：已有同部位时提示还在恢复，新部位才追加。只有“没有伤病/都好了/全好了/康复了/恢复了”且没有指定部位时才全清。
- `diet.meal_detail` 支持“今天午餐吃什么”“晚餐菜谱怎么做”“看看今天的餐单”；读取已保存餐单的食材、配料和做法，没有保存餐单时提示先生成，不凭空编菜谱。
- `diet.dislike_food` 支持“不喜欢吃鸡胸肉”“以后别安排西兰花”“可以吃鸡胸肉了”；写入食物避开列表，可撤销，并按普通食物/自定义食物匹配。生成单日和一周餐单时提示词与确定性后置过滤都会排除该食物，用同类食材替换；历史已保存餐单不自动改，重新生成后生效。`/sync` 增加 `disliked_foods`，旧 iOS 不发送该字段也不会清空服务端记录。
- `profile.update_equipment` 支持“我有哑铃和弹力带”“我的器械是徒手”“去掉弹力带”“家里没有器械”；更新档案器械，确认后可撤销。若当前计划有动作需要被移除的器械，会在卡上提示，但不会自动改计划；个人器械库仍是精确器械来源。
- 加练执行前会再次检查同一周/星期是否已有训练，过期卡不会写出重复训练日。
- 仍未做：更多能力加入 batch、训练中/资料设置类动作。
- 已补：食物/体重/力量/有氧卡会检测同日同餐同食物、同日相同身体数据、同日相同力量组或有氧时长，显示“确认会再记一次”警告；不静默阻止。batch 卡会汇总子动作的重复警告；warning 只提示，不阻止确认。

## 9. 新能力接入标准

新增一个教练动作时，必须同时补：

1. `Capability`（id/domain/kind/refresh/undo/events）
2. `manifest.py` 的 `ActionSpec`（examples/slots/card）
3. resolve / execute / undo
4. 确认卡/结果卡（优先复用通用卡）
5. 权限与安全边界
6. 单测：路由、槽位、确认、撤销、刷新域
7. 生产烟测

不允许只加页面、不加教练 action。
