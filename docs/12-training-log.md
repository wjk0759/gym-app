# 12 · 训练记录深度迭代（对标训记）

这版不调整底部 Tab 和整体视觉，只补训练记录产品最核心的“数据护城河”。

## 这版补了什么

| 训记能力 | FitAI 当前实现 |
|---|---|
| 每组重量、次数、RPE | 已有，训练中逐组记录 |
| 上次重量自动带入 | 已有，开始动作时读取上次记录 |
| 组间休息计时 | 已有 |
| 训练容量 = 组数 × 重量 × 次数 | 已有，并用于周复盘 |
| 训练月历/日容量 | 新增训练记录页，按月查看每天容量 |
| 历史训练列表 | 新增训练记录页，点日期筛选当天记录 |
| 动作历史 | 新增动作历史页，可从训练详情进入 |
| 动作容量趋势 | 新增最近 8 次该动作的容量柱状图 |
| 个人 PR | 新增历史最佳组：先比重量，再比次数 |
| 训练心得 | 训练总结可填写，训练详情可查看和编辑 |
| 训练数据统计 | 新增本月训练次数、容量、总分钟、动作数 |

## 入口

- 今日 → 最近训练 → 全部记录
- 训练详情 → 每个动作 → 历史
- 训练完成总结 → 训练心得

## 这版刻意没有照搬

- 400+ 动作库：先把已有动作库做深，不追求数量。
- 自定义动作：需要和计划、动作历史、PR 的数据结构一起设计，下一版做。
- 训练模板分享：先保证个人计划和历史版本可用。
- Apple Watch / HIIT / 社区：依赖真实设备和后续版本，不在本轮堆功能。
- 没有改 Tab、没有合并今日/计划、没有增加新的底部入口。

## 跨设备同步（2026-10）

- 完成训练后，本地记录通过 `POST /api/v1/workouts` 上报；未联网时保留 `syncedAt == nil` 的创建队列。
- 训练详情编辑通过 `PATCH /api/v1/workouts/{id}` 同步，失败时保留 `pendingRemoteUpdate`，下次前台刷新自动重试。
- 删除已同步记录时先落地 `remoteID` 墓碑，再调用 `DELETE /api/v1/workouts/{id}`；离线删除不会被下一次拉取复活。
- iOS 前台/登录后通过 `GET /api/v1/workouts?from=...&include_sets=true` 拉取近 90 天记录，按 `remoteID` 合并；本机未上传的修改优先。
- `program_day_id` 会随创建/更新上报，并在拉取时用于恢复训练日标题；旧记录没有关联时显示「训练记录」。
