# 20 · UI 自查、信息架构与前端模块边界

## 这轮自查发现的问题

1. 滚动页面时，内容会从状态栏和吸顶返回头之间露出一条卡片，看起来像顶部多了一块空白模块。
2. 单个训练心得没有上限，一段长文本可以把训练详情撑到几千像素。
3. 首页仍在展示「最近训练」，计划和训练数据页也能看到训练记录，入口和职责重复。
4. 日历选中休息日时只能看，不能补录这天的训练。
5. 饮食拍照和器械拍照各自维护一套相机 UI，交互和失败回退不一致。
6. 首页日期、问候语、周次和累计容量有硬编码，和真实状态不一致。
7. 计划生成的次数还是 `8-10` 区间，与「次数只保留单个数字」的规则冲突。
8. Web 预览所有页面、组件、状态和动作都堆在 `preview/app.js`，难定位、难复用。

## 处理结果

### 顶部与滚动

- `.status-scrim` 覆盖到页面内容起点，使用不透明背景，不再让滚动内容从状态栏下方透出。
- 页面返回头继续吸顶；长列表滚动时头部不跳、不露出后方卡片。
- 相机页单独使用全屏模式，不参与普通页面状态栏遮罩。
- 280 / 320 / 390 / 430 / 844 × 390 均已检查无横向溢出。

### 文本与输入

- 训练名称上限 40 字；训练心得上限 300 字，编辑页显示实时计数。
- 训练详情的心得最多显示 6 行，超出截断；旧数据超长也不会撑爆页面。
- 聊天、资料昵称、伤病描述、食物名称、搜索词、器械名称和备注均设置合理上限。
- 全局正文允许断长单词；聊天气泡和心得预览显式 `overflow-wrap: anywhere`。

### 信息架构

- 首页只保留：目标进度、今日训练 / 饮食计划双主卡、本周进度、AI 复盘。
- 计划 Tab：数据复盘摘要 → 月历 → 选中日期 → 计划摘要；点击摘要进入独立 `planReview` 报告页。
- 报告页为单屏 6 KPI + 训练 / 饮食摘要 + 最近训练，390×844 和 280×844 不滚动；最近训练点击直接打开详情。
- 日历支持今天 / 过去日期补录训练；未来日期只编辑计划。
- 补录训练复用训练详情编辑器和动作库选择器，不新建第二套表单。

### 相机与媒体

- Web：`js/components/camera.js` 统一饮食和器械拍摄页；`js/components/exercise-analytics.js` 统一动作训练数据。
- iOS：`Core/Media/PhotoCaptureView.swift` 统一饮食、器械、体型照片和器械库添加照片。
- 删除旧 `CameraPicker`，只保留一套相机权限、失败回退和相册入口。

### 数据正确性

- 首页日期使用真实日期；问候语按当前时段生成。
- 周次按计划起始周计算；本周完成和本周容量按真实 session 日期计算。
- 累计容量按 sessions 聚合，不再写死 `18,400`。
- 计划次数生成和旧计划读取都规范为单个数字。
- 训练记录补录写入真实 `timestamp`，月历、训练数据、最近训练同步更新。

## Web 代码边界

```text
index.html              加载顺序 / 缓存版本
css/base.css            令牌、外壳、通用组件、页面基础
css/coach.css           AI 教练对话与调整方案
css/body-checkin.css    身体数据提醒 / 弹层
css/equipment.css       器械详情 / 相机 / 选择器
css/adaptive.css        自适应基础
css/workout.css         编排与训练中调整
css/plan.css            计划日历 / 数据复盘 / 训练日期
js/data.js              静态数据、演示数据、计划生成
js/demo-food-history.js 演示饮食历史（周/月/年复盘）
js/state.js             状态、持久化、派生数据
js/router.js            路由栈、上一级返回、深链接 fallback
js/ui.js                通用外壳
js/components/*.js      共用相机、数字选择器、拖拽滚动、动作训练数据
js/coach-adjustment.js  教练主导的计划调整逻辑
js/plan-review.js       独立周 / 月 / 年数据复盘页 + 目标接近度
js/plan-schedule.js     未来 4 周训练日期选择页
js/period.js            女性经期区间与训练模式选择页
js/body-checkin.js      身体数据提醒表单与调度
js/training-data.js     动作详情进入的单动作训练数据页
js/<page>.js            页面渲染
js/actions/<feature>.js 页面动作，按功能注册到 window.app
js/runtime.js           路由 render
js/boot.js              启动
scripts/check-preview.js 模块检查
```

规则：

- 页面渲染和动作分离。
- 共用组件先提取到 `components/`，不在页面文件复制第二份。
- 单文件过大优先继续拆，不继续往后追加。
- 新文件必须加入 `index.html` 的明确加载顺序。
- `node scripts/check-preview.js` 阻止重复全局符号和单文件回退。

## iOS 代码边界

- 页面按 Feature 拆分：`Features/Home`、`Plan`、`Workout`、`Equipment`、`Coach`、`Profile`。
- 通用组件：`Core/Design/MetricControls`、`Core/Design/AppLayout`、`Core/Media/PhotoCaptureView`。
- 训练编排：`Features/Workout/CustomWorkoutBuilderView`，今日训练、自选训练、计划训练日共用。
- 训练记录：`WorkoutDetailView` 同时负责查看、编辑和从日历新建；新建通过 `isNew` 参数复用同一套字段和动作库。
- 器械选择：`EquipmentPickerView(onSelect:)` 同时服务训练记录编辑和计划训练日编辑。
- 相机：饮食、器械、体型、器械库添加照片共用 `PhotoCaptureView`，旧的 `CameraPicker` 已删除。
- 计划调整：`PlanAdjustmentCoach` 扩展 + `CoachChatView` 阶段 UI；首页 / 计划页先跳教练，不直接改计划。
- Tab 切换：`MainTabView` 绑定 `AppStore.selectedTab`，调整请求可以从首页 / 计划定向到教练。

## 验收清单

- 训练详情长列表滚动时顶部无空白卡片。
- 训练心得超 300 字被限制；旧超长记录在详情页最多 6 行。
- 首页不再出现「最近训练」卡片。
- 计划 Tab 顶部摘要有「查看报告」入口，进入独立周/月/年数据复盘页；页面含 6 KPI、训练 / 饮食摘要和最近训练，常规手机高度不滚动。
- 计划支持日历补录和未来 4 周训练日期选择；日期页采用紧凑 4×7 日历板，不再展示大段说明。
- 动作详情不再有 06 训练数据；单个动作训练数据只从动作详情「数据」进入，返回动作详情。
- 饮食 / 器械 / 体型照片使用同一套拍摄页。
- 调整计划先进入 AI 教练对话，方案确认后才修改计划。
- 计划次数显示单个数字。
- 首页日期、问候、周次、容量随数据变化。
- 资料编辑的「保存」固定在吸顶页头右上角，长表单不需要滚到底；左上角返回仍取消修改。
- 保存目标、分化、每周频率、单次时长、经验或器械变化时，自动重排 4 周计划并更新计划版本；训练日期页立即使用新频率和分化。
- 计划生成按已选器械过滤动作；器械库的额外动作也必须属于已选器械，未选器械的动作不会出现在计划中。
- AI 教练输入区增加拍照按钮，复用共享相机页；拍照后把照片消息发进对话，教练先追问要检查动作、器械还是不适部位。
- 身体打卡只保留体重、体脂、腰围；腰围单独整行展示。臂围 / 大腿围在资料编辑中维护，不进入每次打卡弹窗。「今天隐藏 / 关闭自动提醒」改为成对次级按钮。
- 首页目标卡按最新身体数据更新进度；设置目标日期和记录今日数据后立即反馈。目标支持体重、腰围和体脂率；身体数据支持臂围和大腿围。
- 女性用户计划页提供「经期」入口：月历先选开始、再选结束，设置经期区间；计划日历标记经期。
- 经期支持轻重量训练 / 直接休息两种安排：轻量模式自动少 1 组、负重约 80%；休息模式首页显示恢复日、不启动力量训练，计划和历史记录保留。AI 教练回答同步区分两种模式。
- Web 预览由多个 JS / CSS 模块组成，旧 `app.js` / `styles.css` 单文件已删除。

## 2026-10 视觉收口

- 首页新增目标进度卡：当前目标、距目标体重、起始 / 当前 / 目标、腰围目标、完成百分比、目标日期和剩余天数。目标卡从资料页迁到首页，资料页不再重复展示。
- 目标进度按身体指标时间线的起始体重和最新体重计算；记录今日数据打开身体数据打卡，保存后进度、当前值、今日打卡状态立即更新。
- 目标日期可在首页直接设定；日期只影响剩余天数和节奏，不重置已有进度。
- 首页把「AI 复盘」和「本周完成」合并为一张 AI 教练 · 本周进度卡，保留完成率、RPE、容量和调整入口，去掉重复卡片。
- 首页「今日饮食」从小入口升级为完整饮食计划卡：日目标 / 剩余热量、四项宏量、下一餐建议、记录饮食和调整饮食。
- 训练日顺序为训练 → 饮食；休息日顺序为饮食 → 恢复，休息卡不再放教练 CTA。
- 首页教练动作不再重复叫「找教练」：训练卡只开始训练，AI 卡调整训练计划，饮食卡调整饮食；饮食调整进入营养教练上下文。
- 首页 AI 调整入口改为 44px 高的整行按钮，首屏可见，不再使用小号文字链。
- 计划页不再提供动作数据入口；顶部摘要进入独立整体数据复盘页，支持本周 / 本月 / 今年与上期同进度对比。
- 复盘 KPI：训练次数、平均每日时长、日均摄入、热量缺口、体重、体脂；每项显示上期值、差值和方向。
- 颜色统一按目标接近度：接近目标绿色，远离红色，持平灰色；体重优先按目标体重判断距离。
- 饮食明细补膳食纤维；身体指标使用体重/体脂时间线，保存身体数据后复盘立即更新。
- 身体数据提醒默认关闭，可设置每周 / 每两周 / 每月；到达日期打开今日页弹出，保存或隐藏后本次消失。
- 底部 TabBar 的选中背景改为滑动指示块，切换 Tab 时从旧位置缓动到新位置，不瞬移。
- 登录未勾选协议时不再显示表单报错，改为确认弹窗；点「同意并登录」自动勾选协议并继续手机号 / 微信 / QQ 登录。
- 计划支持选择未来 4 周的具体训练日期：每周按目标次数点选；训练内容按日期顺序排入；历史记录不变。
- 建档和资料页支持 1/3/5 分化；每周训练支持 1–7 天，单次时长最高 120 分钟。
- AI 生成计划按分化 + 每周训练次数选择模板，计划标题显示分化；5 分化按胸 / 背 / 腿 / 肩 / 手臂编排。
- 动作训练数据页去掉重复的「动作训练数据」眉题，改为「当前动作」；页面说明不再写内部迁移信息。
- AI 方案出现时聊天优先对齐方案卡顶部，顶部裁切内容加渐隐；计划调整中隐藏「清空」按钮，避免误删上下文。
- 器械详情统一使用线性动作图标，不再混用 emoji；视频、轨迹、角度占位也使用同一套图标。
- 训练中的「跳过动作」从弱文字链改成明确的次级按钮样式。
- 示例数据提示缩短为 1.4 秒，避免首屏截图和关键按钮长时间被 toast 遮挡。
- 280px 下训练数据标题、四个指标改为两列网格；动作数据三项指标改为两列 + 第三项整行，容量数值不再断行。
- 线性图标统一覆盖器械详情、器械库、器械识别、饮食拍照、相机、删除、Pro 皇冠；emoji 只保留训练感受和餐食示意等带情绪/内容语义的场景。
- 饮食记录加号、删除按钮扩大触控面积；删除按钮补 aria-label。
- 动作训练数据横向动作条接入桌面鼠标拖拽、触摸惯性滚动和横向越界隔离，不再出现“划不动”。
- Web 返回按钮统一走路由栈，不再按页面写死返回目标；路由清单见 `docs/22-web-routing.md`。
