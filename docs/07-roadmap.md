# 07 · 开发路线（12 周 MVP）

> 假设：1 名 iOS + 1 名后端/AI，设计兼职，内容（动作视频）外包。
> 如果只有你一个人，把周期乘以 1.8–2.2，或砍掉 P1。

## 阶段总览

| 阶段 | 周 | 目标 | 出口标准 |
|---|---|---|---|
| S0 准备 | W0–W1 | 环境、账号、原型 | Mac 可编译，Figma 主流程可点 |
| S1 地基 | W1–W2 | 工程骨架、数据库、鉴权 | App 能登录、建档、持久化 |
| S2 计划 | W3–W4 | 生成 + 校验 + 编辑 | 20 次生成 ≥19 次通过 |
| S3 训练 | W5–W6 | 执行、记录、通知 | 真机锁屏提醒；离线可练 |
| S4 教练 | W7–W8 | 问答、记忆、复盘 | 安全问题 100% 兜底 |
| S5 识别 | W8–W9 | 拍照识别 + 动作卡片 | Top-3 ≥85% |
| S6 饮食 | W10 | 热量计算 + 饮食建议 | 公式可复核 |
| S7 内测 | W11 | TestFlight、埋点、修 bug | 20 人内测无阻断 |
| S8 提审 | W12 | 备案、素材、提审 | 通过审核 |

## 逐周任务

### W0–W1 准备

- [ ] 确定产品名、Bundle ID、公司主体
- [ ] 注册 Apple Developer（公司账号需 D-U-N-S，预留 2 周）
- [ ] 准备 Mac 或云 Mac（MacinCloud / MacStadium）
- [ ] Figma 画 8 个核心页面
- [ ] 申请 DeepSeek / 通义 / 豆包 API
- [ ] 启动 App 备案、ICP 备案
- [ ] 确认教学视频方案（自拍/采购）

**出口：** `xcodegen generate` 后能在模拟器跑起来。

### W1–W2 地基

- [ ] 后端：用户、档案、目标、动作库 seed
- [ ] iOS：Onboarding、档案编辑、本地持久化
- [ ] 登录：开发期 X-User-Id → 后期 Sign in with Apple
- [ ] 隐私政策与单独同意弹窗（先占位）

**出口：** 建档完成率可埋点；杀进程后数据不丢。

### W3–W4 计划

- [ ] Prompt v1 + JSON Schema
- [ ] 校验器（动作/器械/伤病/负荷）
- [ ] 规则模板降级
- [ ] iOS 计划展示、周切换、换动作、改组次
- [ ] 计划版本化

**出口：** 评测集 100 组，JSON 合法率 ≥95%，禁忌动作 0。

### W5–W6 训练

- [ ] 训练执行页、组记录、休息计时
- [ ] 本地离线队列 + 幂等上报
- [ ] 通知调度（每周重复 + 改计划替换）
- [ ] 历史列表、周统计
- [ ] iOS 26 AlarmKit 验证（失败则回退通知）

**出口：** 真机锁屏按时提醒；飞行模式完成一次训练后联网成功同步。

### W7–W8 教练

- [ ] RAG 知识库（动作库 + FAQ）
- [ ] 流式对话
- [ ] 安全兜底规则
- [ ] 周复盘 + 调整规则
- [ ] 用户确认/拒绝调整

**出口：** 40 条红旗描述 100% 触发兜底；调整建议可追溯到训练数据。

### W8–W9 器械识别

- [ ] 图片上传（压缩、EXIF 清除、OSS 直传）
- [ ] 视觉模型 + 器械库匹配
- [ ] 低置信度确认流程
- [ ] 动作详情 + 视频播放
- [ ] 手动搜索兜底

**出口：** 30 类器械 Top-3 ≥85%；识别失败可 10 秒内手动找到动作。

### W10 饮食

- [ ] BMR/TDEE 公式
- [ ] 三餐模板
- [ ] 手动记录
- [ ] 外卖入口（有资质才开）

**出口：** 计算结果可被营养师复核；不给出疾病饮食处方。

### W11 内测

- [ ] TestFlight 20 人
- [ ] 埋点：建档、生成、开练、完成、次留
- [ ] 崩溃与卡顿修复
- [ ] 隐私标签、商店素材
- [ ] 客服与反馈入口

**出口：** 崩溃率 <0.5%；核心闭环无阻断。

### W12 提审

- [ ] App 备案号、AI 登记号
- [ ] 隐私政策 URL、用户协议、免责声明
- [ ] 订阅配置（如上线）
- [ ] 审核备注：说明 AI 用途、数据来源、非医疗建议
- [ ] 提交审核

**出口：** 通过或拿到明确拒审原因并可 3 天内整改。

## 人员配置

| 角色 | 投入 | 职责 |
|---|---|---|
| iOS | 1 全职 | SwiftUI、通知、相机、StoreKit |
| 后端/AI | 1 全职 | API、Prompt、校验、部署 |
| 设计 | 0.3 | 设计系统、关键页面 |
| 内容/教练 | 0.3 | 动作库审核、视频、计划规则 |
| 运营 | 上线后 | 客服、内容、合规 |

| 项 | 金额 |

| 云服务 | 500–3,000 元/月 |
| 模型 API | 500–5,000 元/月 |
| 视频（30–50 个动作） | 1–5 万元 |
| 设计 | 1–3 万元 |
| 备案/软著/法律 | 1–4 万元 |
| **合计（自研）** | **约 5–15 万元** |

## 里程碑验收（Go / No-Go）

| 节点 | 不通过就停下来 |
|---|---|
| W4 | 计划合法率 <90% → 先修校验与模板，不继续做 UI |
| W6 | 通知在真机不稳定 → 改为站内提醒 + 服务端推送，别硬磕 AlarmKit |
| W8 | 安全问题漏判 → 暂停上线，补规则与人工审核 |
| W9 | 识别 Top-3 <70% → 降级为“手动搜索 + 拍照辅助”，不宣传 AI 识别 |
| W11 | 次留 <25% → 先改留存，不急着投放 |
