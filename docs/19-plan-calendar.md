# 19 · 计划日历、数据复盘与训练日编辑复用

## 目标

计划 Tab 不再以「第几周 + 训练日卡片」作为首页，而是以月历作为入口：

- 点击日期查看当天的训练、饮食和计划。
- 过去日期可以查看 / 编辑训练记录与饮食记录。
- 未来日期可以查看 / 编辑训练计划。
- 计划 Tab 用月历管理训练日 / 饮食；顶部数据复盘摘要进入独立的 `planReview` 报告页，报告不内嵌在计划页。
- 动作训练数据只从动作详情的「数据」按钮进入；计划页不再提供动作数据入口。
- 首页的「最近训练」列表并入计划 Tab，首页只保留今日、周进度、饮食和 AI 复盘。
- 编辑训练日不再维护第二套编辑器，直接复用训练编排、动作库和数字滚轮组件。
- 支持选择未来 4 周的具体训练日期：训练内容不变，按日期顺序排入；每周按目标次数限制。
- 日历可以补录任意过去 / 今天训练；补录页复用训练记录编辑器和动作库选择器。
- 饮食 / 器械拍摄共用同一套拍摄页，不再各自维护相机 UI。

## 日历

```text
计划 Tab
├── 数据复盘摘要（本周 / 本月 / 今年，点击跳到完整报告）
├── 月历
│   ├── 月份切换 / 回到今天
│   ├── 周一至周日
│   ├── 日期格
│   │   ├── 完成训练：实心主色点
│   │   ├── 训练计划：空心主色点
│   │   └── 饮食记录：橙色点
│   └── 图例
├── 选中日期详情
│   ├── 训练
│   │   ├── 已完成的训练记录 → 训练详情
│   │   ├── 计划训练日 → 编辑内容 / 调整周几
│   │   ├── 记录 / 补记这天的训练（今天及过去）
│   │   └── 无安排 → 休息日
│   └── 饮食
│       ├── 当天热量 / 蛋白质
│       ├── 记录列表
│       └── 查看 / 修改当天饮食
└── 当前计划摘要 + 调整训练日期 / 教练调整

planReview 报告页
├── 本周 / 本月 / 今年切换 + 同进度对比
├── 6 个 KPI：训练次数 / 平均每日时长 / 日均摄入 / 热量缺口 / 体重 / 体脂
├── 训练明细：容量 / 组数 / 单次分钟 / 完成训练
├── 饮食营养：热量 / 蛋白质 / 碳水 / 脂肪 / 膳食纤维
└── 最近训练记录
```

- 日历按计划训练日的实际 `dateKey` 显示；调整日期后，月历计划点、首页今日训练和训练数据同步更新。
- 点击相邻月份日期会同步切换月份；月份切换在窄屏和横屏下都不产生横向滚动。
- 训练、计划和饮食三种信息使用独立圆点，不使用颜色相近的整格背景。
- 选中日期使用主色描边与轻主色底；今天使用较弱主色描边。
- 日期格、图例、日详情和底部操作区均使用自适应 gutter 与安全区。

## 数据复盘

计划 Tab 顶部显示数据复盘摘要，点击「查看报告」进入独立 `planReview` 页面：

- 报告页在 390×844 和 280×844 下均为单屏布局，不需要滚动；短屏才允许内部滚动。
- 页面只保留报告本身：周期、6 个 KPI、训练 / 饮食摘要和最近训练，不重复计划页的操作说明。
- 周期：本周 / 本月 / 今年，分别对比上周同期 / 上月同期 / 去年同期。
- 当前周期和上期都按同一进度截止，避免本周刚开始就拿完整上周比较。
- 训练 KPI：训练次数、平均每日时长；卡片显示当前值、上期值、差值和方向箭头。
- 饮食 KPI：日均摄入、热量缺口（目标热量减日均摄入）、有记录天数。
- 身体 KPI：体重、体脂；数据来自身体指标时间线，资料保存时会追加当天测量。
- 颜色统一按“接近目标”：更接近目标绿色，远离目标红色，持平灰色，无上期数据弱化。
  - 训练次数 / 平均每日时长：上升为接近目标。
  - 日均摄入 / 热量缺口：离目标热量更近为绿色。
  - 体重：按目标体重判断。增肌时 72.5 → 76 方向向上为绿色，减脂时向下为绿色。
  - 体脂：下降为绿色。
- 体重方向不再固定按“增肌 / 减脂”标签，而是优先按用户设定的目标体重计算距离。
- 训练明细：总容量、总组数、单次分钟、完成训练。
- 饮食明细：有记录日均热量、蛋白质、碳水、脂肪、膳食纤维，并显示目标值。
- 计算时未记录的饮食天不计入均值，避免把记录缺失误判成摄入不足。
- 最近训练放在报告页底部，直接打开同一条 `session` 详情，编辑能力与训练历史页一致。
- 「全部训练」进入训练记录页。
- 动作训练数据的入口只保留在动作详情的「数据」按钮；计划页不再出现「动作数据」。
- 动作数据页继续复用容量 / 重量 / 1RM / 周期 / 指标 / 实际日期折线图。

## 身体数据提醒

- 默认关闭，用户在「我的 → 设置 → 身体数据提醒」选择：
  - 关闭
  - 每周（选择周一至周日）
  - 每两周（选择周几，按启用周起算）
  - 每月（1–28 日）
- 到日期后，打开「今日」Tab 弹出底部身体数据卡。
- 卡内填写体重和体脂率，保存后：
  - 写入当天身体指标时间线
  - 同步个人资料体重 / 体脂
  - 今日不再弹出
  - 月 / 年数据复盘立即使用新数据
- 用户可以「今天隐藏」或「关闭自动提醒」，两种操作都会让本次弹窗消失。
- 如果当天已经记录过身体数据，不会再次弹出。
- 弹层不是路由；不进入 `routeStack`。

## 调整训练日期

- 计划页顶部和计划摘要提供训练日期入口；选中计划日只保留「编辑内容」，不再重复放调整日期。
- 打开 `planSchedule` 页面，用一张紧凑的 4 周 × 7 天日期板展示未来 4 周，不再放大段说明卡。
- 每周需要选择与当前计划一致的训练日数量（例如 3 练选 3 天），点日期即可选中 / 取消。
- 不能在同一周超过目标训练日数；少于目标时禁止保存并提示还差几天。
- 保存后按日期顺序把该周训练内容（动作、组数、次数、负重）映射到新日期。
- 日历计划点、首页今日训练、训练数据随日期更新；历史训练记录和饮食记录不变。
- 先保存为草稿，点击「保存训练日期」才写回；返回或取消丢弃草稿。
- 这里调整的是具体日期，不再使用“周几交换”的旧交互。

## 训练分化

- 用户初始建档时可选择 1 / 2 / 3 / 4 分化：
  - 1分化：全身
  - 2分化：上下肢
  - 3分化：推 / 拉 / 腿
  - 4分化：胸肩 / 背 / 腿 / 手臂
- `用户资料 → 训练安排` 可修改分化；保存后需要重新生成计划才会应用。
- AI 生成计划时按分化 + 每周训练日数选择模板：
  - 分化决定动作分组和训练日标题；
  - 每周训练日数决定一周排几天；
  - 具体日期默认落在未来，后续可在 `planSchedule` 里继续调整。
- 计划标题显示目标、分化和每周训练次数。

## 编辑训练日复用

### Web

- 日历的「编辑训练日」调用 `editPlanDay`，把计划日转成 `workoutDraft`，来源标记为 `planEdit`。
- 页面直接进入 `workoutComposeScreen()`，复用：
  - 拖拽排序
  - 组数 / 次数 / 休息滚轮
  - 重量输入
  - 总组数和预计时间
- 底部主按钮在 `planEdit` 模式切换为「保存训练日」。
- 「从动作库添加动作」复用 `equipmentPickerScreen()` 的 `planExercisePicker` 模式，不再实现第二套动作选择器。
- 选择动作后回到同一个编排页草稿；保存才写回 `state.plan.days`。
- 取消或返回不修改计划。

## 补录训练复用

- 选中今天或过去日期，选中日期详情显示「记录这天的训练 / 补记一次训练」。
- 训练日活动会预填该日计划动作、组数、次数和重量；休息日从空记录开始。
- 补录页面复用训练详情编辑模式、训练名称 / 时长 / 感受 / 心得字段和动作库添加。
- 保存后写入真实 `timestamp`，月历点、训练数据、最近训练和首页周进度同步更新。
- 未来日期不显示补录入口，只提示先编辑计划。

## 共用拍摄页

- Web `components/camera.js` 提供 `photoCaptureScreen(context)`；饮食和器械只传入标题、提示和拍摄后的回调。
- 相机页统一取景框、相册回退、拍照按钮和错误提示；不再维护两套全屏相机。
- iOS `Core/Media/PhotoCaptureView` 服务 `FoodPhotoAnalysisView`、`EquipmentRecognitionView`、`BodyPhotoAnalysisView` 和器械库添加照片；权限失败和相册回退逻辑只有一份。
- 旧的 `CameraPicker` 已删除，避免系统相机与自定义相机两套交互并存。
- 饮食识别进入时直接启动共用拍摄页；器械识别同样。

### iOS

- `PlanEditorView` 只保留一个薄包装，内部使用 `CustomWorkoutBuilderView(editing:onSave:)`。
- `CustomWorkoutBuilderView` 增加 `.editPlan` 模式：
  - 保留训练日 id、周次和星期
  - 底部改为「保存训练日」
  - 保存时规范化组数、单值次数、休息和重量
- 动作库添加复用 `EquipmentPickerView(onSelect:)`，与训练记录编辑、动作库使用同一套筛选和搜索。
- 编排页的滚轮、重量输入、拖拽手柄、删除按钮与今日训练 / 自选训练完全一致。
- 计划日编辑以全屏 cover 呈现，取消不会写入计划。

## 饮食日期

- Web 的 `foodLogs` 增加 `date` 字段，旧数据自动归到今天。
- `nutritionTotals(dateKey)` 按日期过滤；饮食页使用 `nutritionDateKey`。
- iOS 的 `NutritionView(date:)`、`AddFoodView(date:)`、`FoodPhotoAnalysisView(date:)` 都接收日期，新增饮食记录写入所选日期。
- 从日历进入历史日期饮食后，返回计划 Tab；从今日页进入仍返回今日页。
- 日历只显示当天是否有饮食记录的圆点，不显示具体食物，避免日历信息过载。

## UI 自查与文本约束

- 顶部状态栏与吸顶返回头之间使用不透明遮罩，滚动长列表时内容不会从状态栏下方露出一条「多余卡片」。
- 训练名称最多 40 字；训练心得最多 300 字，编辑页显示实时计数。
- 长心得在详情页最多展示 6 行并截断，避免一条记录把页面撑成几千像素。
- 全局文本允许任意长单词断行，搜索 / 名称 / 聊天输入均设置上限。
- 首页日期、问候语、本周周次、累计容量全部按真实日期和状态计算，不再硬编码。
- 计划页、独立复盘页和训练日期页在 280 / 390 宽都不横向溢出。
- 数据复盘的营养指标包含热量、蛋白质、碳水、脂肪、膳食纤维；旧饮食记录自动补齐纤维字段。

## 验收

- 计划 Tab 首屏是月历，不再是周选择器。
- 月历能标记过去训练、未来计划和饮食记录。
- 点击过去训练日期能打开并编辑训练记录。
- 点击任意日期能查看饮食并添加 / 修改当天记录。
- 点击今天 / 过去日期能补录训练，未来日期只允许编辑计划。
- 点击未来计划日期能进入与今日训练相同的编排组件编辑训练日。
- 点击计划页「查看报告」进入独立报告页，可切换本周 / 本月 / 今年，查看 6 KPI、训练 / 饮食摘要和最近训练；首页不再重复显示最近训练。
- 报告页在 390×844 和 280×844 下完整单屏显示，不需要滚动。
- 数据复盘按目标接近度显示绿 / 红 / 灰；无上期数据显示数据不足。
- 身体数据提醒设置为每周 / 每两周 / 每月后，到日期打开今日页弹出；保存或隐藏后消失。
- 计划页不出现「动作数据」入口；动作详情「数据」按钮进入动作训练数据，返回动作详情。
- 训练日期页使用紧凑 4×7 日期板，390 / 280 宽均单屏显示，不需要滚动。
- 选择训练日期后，4 周计划、月历计划点、首页今日训练同步变化；历史训练记录不变。
- 训练心得超过 300 字会被限制，详情页不会出现超长文本溢出。
- 训练详情和饮食页滚动时顶部没有多余空白卡片或内容穿透。
- 编辑训练日保存后，月历上的计划点、动作数和动作列表立即更新。
- 280 / 320 / 375 / 390 / 430 宽度和 844 × 390 横屏不出现横向溢出。
- 底部 Tab 栏不遮挡可滚动内容，底部安全区留白有效。
