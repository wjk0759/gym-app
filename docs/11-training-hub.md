# 11 · 训练 Tab 合并与复盘模块

## 1. 产品经理 / UI 设计师结论

### 产品经理视角
- “今日”是用户现在要做什么，“计划”是用户怎么编排，“复盘”是用户如何根据结果调整。三者属于同一条训练闭环，不应该拆成两个底部 Tab。
- 如果只是把复盘做成“今日”里的一张卡片，用户只有在刷首页时才会看到；复盘需要有稳定的入口。
- 但也不应该为了复盘再加第 6 个底部 Tab，底部 Tab 过多会稀释主任务。

### UI 设计师视角
- 底部 Tab 控制在 4 个：训练、教练、器械、我的。
- 训练内部用原生分段控件承载“今日 / 计划 / 复盘”，既保留层级，又避免嵌套 Tab。
- 今日保留执行入口，计划保留编辑入口，复盘只做数据和调整，减少同一功能在多个页面重复出现。
- 切换使用系统分段控件，保持果味、低学习成本。

## 2. 最终信息架构

```text
TabBar
├── 训练
│   ├── 今日（执行）
│   │   ├── 今日训练
│   │   ├── 本周完成
│   │   ├── 今日饮食
│   │   └── 最近训练
│   ├── 计划（编排）
│   │   ├── 当前计划
│   │   ├── 周切换
│   │   ├── 训练日编辑
│   │   └── 计划版本历史
│   └── 复盘（反思）
│       ├── 本周数据：完成率 / RPE / 训练容量
│       ├── 下版建议与调整预告
│       ├── 生成本周调整版
│       └── 本周训练记录
├── 教练
├── 器械
└── 我的
```

## 3. 迁移规则

- 原来的“今日”和“计划”入口不再是两个底部 Tab。
- 今日页里的 AI 复盘卡片迁出到“复盘”，避免重复。
- 计划页只负责查看、编辑和重新生成，不再重复放“复盘并调整”主按钮。
- 复盘生成新版本后，旧版本仍可在计划版本历史中恢复；训练记录不被覆盖。
- 从训练日编辑页返回时回到“计划”；训练结束后回到“今日”；查看训练明细后回到“今日”。
- 点底部“训练”时保留上一次所在的训练子页；用户可用分段控件明确切换。

## 4. 复盘模块原则

复盘不是健康评分，也不是对用户的评价。它只回答一个问题：

> 根据这周实际完成的训练，下一版计划应该更难、更轻，还是暂时保持？

当前算法：

| 条件 | 调整 |
|---|---|
| 完成率 < 60% | 每个动作减少 1 组，先恢复规律 |
| 平均 RPE ≥ 9 | 主项重量下调 5% |
| 完成率 ≥ 80% 且 RPE ≤ 8 | 主项重量上调 2.5% |
| 其他 | 保持当前负荷，优先补齐训练日 |

## 5. 验收标准

- [ ] 底部 Tab 只有 4 个，名称为训练 / 教练 / 器械 / 我的
- [ ] 训练页可以切换今日 / 计划 / 复盘
- [ ] 今日页不再显示重复的 AI 复盘卡片
- [ ] 计划页不再显示重复的复盘调整按钮
- [ ] 复盘页在无计划、无本周训练时有明确空状态
- [ ] 复盘生成调整版后，旧版本可在计划历史恢复
- [ ] 从计划编辑、训练详情返回时落在正确的训练子页
